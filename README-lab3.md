# Оптимізація споживання пам'яті

Програма рахує частоту слів у `src/txt/harry.txt` і виводить топ-30.

## Що оптимізовано

Було (v2): весь файл у `String`, список із 77890 рядків-слів, `Map<String, Long>` з обгортками `Long`, сортування всіх унікальних слів заради топ-30.

Стало (v3):

- файл читається потоком байтів по 64 КБ, а не цілим рядком;
- власна хеш-таблиця: об'єкт створюється лише для унікального слова, а не для кожної появи;
- топ-N збирається купою, без сортування всіх слів.
## Порівняння версій

Медіана з 15 запусків, кожен в окремій JVM. Показано час `Main.main`, пам'ять, виділену за запуск, і найменший `-Xmx`, з яким версія працює.

Книга (0.4 МБ):

- **v0 (оригінал):** 3690 мс, 189.3 МБ, heap 7 МБ.
- **v1 (перший рефакторинг):** 193 мс, 9.7 МБ, heap 7 МБ.
- **v2:** 204 мс, 18.1 МБ, heap 7 МБ.
- **v3 (оптимізована):** 60 мс, 1.2 МБ, heap 2 МБ.
  Книга, повторена 50 разів (21 МБ; v0 пропущено, його час росте квадратично):

- **v1:** 1815 мс, 384.7 МБ, heap 384 МБ.
- **v2:** 2049 мс, 818.7 МБ, heap 384 МБ.
- **v3 (оптимізована):** 275 мс, 1.2 МБ, heap 2 МБ.
## Висновки

- Пам'ять v3 не залежить від розміру тексту: 1.2 МБ і на книзі, і на файлі в 50 разів більшому.
- v3 швидша за v2 у 3.4 раза на книзі і у 7.4 раза на великому файлі.
- Відповідь v2 і v3 однакова (збігається контрольна сума).
- 2 МБ - мінімум самої JVM, справжній мінімум v3 ще менший.
- Ціна: близько 300 рядків коду проти близько 150 у v2.
  Повні результати: `bench/results.txt`.
