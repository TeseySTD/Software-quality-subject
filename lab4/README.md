# Lab 4: швидкість (холодний старт)

Програма рахує частоту слів у `src/txt/harry.txt` і виводить топ-30.
Запуск: `javac -d out src/skoreiko/chnu/edu/*.java && java -cp out skoreiko.chnu.edu.Main [файл] [top_n]`.

## Що оптимізовано

1. **Байти замість `String`:** файл читається одним `readAllBytes()`. Слова не копіюються, таблиця зберігає лише зсув першого входження.
2. **Один прохід:** таблиця `LOWER[256]` одночасно визначає літеру, переводить її в нижній регістр і знаходить роздільник; хеш рахується в тому ж циклі.
3. **Власна хеш-таблиця на `int[]`:** open addressing, записи (хеш, зсув, довжина, лічильник) лежать поруч. Без боксингу й `HashMap`.
4. **Розмір таблиці з довжини файлу:** для звичайного тексту `rehash` не потрібен (у еталонному варіанті розмір був фіксованим).
5. **Холодний старт JVM:** топ-N через відсортований `int[]` вставками; без лямбд, `java.time` і конкатенації рядків (немає `invokedynamic`).

## Результат (JDK 17, `bash bench/run_bench.sh`, медіана свіжих JVM)

Книга (0.4 МБ), повний час процесу JVM:

| версія | час, мс |
|---|---|
| v0 (оригінал) | 2055 |
| v1 | 214 |
| v2 | 142 |
| v3 (lab3) | 140 |
| **v4 (lab4)** | **138** |

Книга x50 (21 МБ): v1 951 мс, v2 268, v3 271, **v4 253**.

Час усередині `Main.main` (без запуску JVM): v3 ~43 мс, **v4 ~10 мс**.

Висновок: сама обробка стала в ~4 рази швидшою, але на малому файлі повний час процесу майже не змінився, бо ~125 мс займає старт JVM. Помітніше виграш на великому файлі.

Слово - це послідовність ASCII-літер `[A-Za-z]+` (80622 слова, 5764 унікальних); v3 працює з іншими правилами (апостроф, стоп-слова), тому результати топу не ідентичні.
